## 本轮确认的问题

| 问题 | 复现与修复 |
| --- | --- |
| Compact 首次尺寸发布失败后仍推进内存状态 | 512px 首片发布元数据失败，下一片却跳过发布并写入 bundle，留下 256px 配置配 512px 数据。通过配置文件不可替换，以及根目录不可写但层目录可写两种方式复现。失败分支恢复未建立尺寸的状态，后续保存必须重新成功发布配置。 |
| 错误中的转义引号导致凭证尾部泄露 | JSON 或引号包围的密码含转义引号和空格时，原正则过早结束匹配，剩余密码进入日志/清单。引用值匹配现在识别反斜杠转义，覆盖双/单引号、多个凭证、连续反斜杠和普通 UTF-8 上下文。 |
| 单条超大服务端错误使失败清单无法保存 | 两条记录中一条约 10.7 MiB 的错误经过 JSON 转义便超过清单的 64 MiB 上限，新增失败无法保存。S3 SDK 的服务端错误消息可进入该路径。脱敏后将单条诊断限制为具名的 4 KiB 项目预算，保留 UTF-8 边界并标注截断；坐标和源指纹不截断。原大消息复现修后保存、加载两条记录成功，永久回归只保留小消息。 |
| 失败报告占用未来输出文件或目录 | `.json` 报告位于 `metadata.json`、Compact 配置或 bundle、MBTiles 数据库及其 `-wal`/`-journal` 路径之下时，首次请求后可能无法保存报告，或创建目录阻塞后续续传。报告本身占用输出目录或其祖先也有同类问题。现在在输出变动之前按路径组件拒绝这些冲突，普通层内 JSON、外部报告和兄弟目录仍允许。 |

修复继续扩展既有测试，不新增测试函数、格式矩阵、测试框架、存储层或公开配置开关。Compact 生产修复只回滚一次失败状态；报告位置检查复用已有路径关系函数；脱敏沿用现有正则处理，不引入通用解析器。

## 验证与边界

专项复现、修复后的既有回归以及独立交叉审查已完成。最终代码使用 Go 1.20.14 执行 `go test -count=1 ./...`，624 项测试及子测试全部通过；`go vet ./...`、`go mod verify`、`git diff --check` 通过。没有新增测试函数或框架；新增子场景对应本轮已确认的路径冲突。

同一提交的自动构建继续验证 Linux 普通/short race 测试、vet、Windows 2022 原生测试、真实 MapProxy 读取和 Go 1.20.14/MSVCRT 双架构发布包，结果及下载见该提交的 GitHub Actions。

4 KiB 是单条日志/报告诊断预算，不是 HTTP/S3 响应体上限、清单总大小或进程总内存保证。整体清单仍有 64 MiB 保存/加载上限，失败记录在运行期间驻留内存；大量短错误仍可能超过该预算。应分批运行长期大量失败的任务，完整恢复使用原范围的 `resume`，不能仅依赖 `repair` 覆盖未记录或尚未调度的坐标。

本轮没有真实 Win7、AWS/MinIO、全球数据量、超大档案上传或断电测试。构建和模拟服务回归不替代这些环境验收，也不构成任意输入下不存在未知问题的证明。
