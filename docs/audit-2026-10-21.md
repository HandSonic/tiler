## 明确边界

- Win7 使用固定 Go 1.20.14、MSVCRT、CGO SQLite，构建 amd64/386，并检查 PE 目标版本和导入。当前环境不能实际启动 Win7；交叉构建成功不等于真机运行验证。
- S3 协议回归使用本地 HTTP 模拟服务，覆盖签名请求、multipart、对象 metadata、条件读、错误和取消；未连接用户真实 AWS/MinIO 账户。
- PMTiles 支持 none/gzip，静态 WebP 可解码但不能编码成 WebP；动画 WebP、Brotli/Zstd/AVIF 明确不支持。
- PBF 不做完整 MVT 内容/schema 推断；拒绝明显的错误页面，非空有效内容及真实图层描述由数据源提供。空文件仍按失败处理。
- 每瓦片大小/像素及覆盖辅助索引分别有预算；worker 和保存队列按数量限制，并非全进程内存上限。Win7 32 位应保持默认低并发（3 fetchers、1 保存缓冲），不要对大瓦片提高到极端并发。
- 归档追加会先合并再重建；目录/S3 散瓦片逐个写入，取消时可能已有部分新瓦片完成。构建不保留跨进程转换断点，恢复能力见 [转换与补洞说明](archive-and-repair.md)。

本记录表示本轮已复现问题被修复，并给出可重复检查的范围；不能证明任何输入、服务和运行环境下都不存在未知问题。

## 数据一致性与覆盖算法再审计

对下载、补洞、本地/S3 转换追加、归档读写和覆盖算法分路审查，再交叉复核修复。以下问题均先用旧实现复现失败，再修复：

- 下载文件元数据在 JSON 转义后可能超过自身 16MiB 读取上限。现在发布前检查最终字节数，失败时保留旧元数据且不请求瓦片。
- 配置中的 tm.description 在配置读取和 Task 初始化两处丢失，现贯通到实际输出。
- 下载 MBTiles 使用裸 SQLite DSN，Unix 目录中的问号会被当作连接参数，导致成功返回但写到错误路径。现复用转义路径的 SQLite 打开函数，覆盖首次下载和恢复。
- 转换替换已有 MBTiles/PMTiles 或追加目录元数据时丢失原权限。现保留既有权限，新文件策略不变；POSIX 权限回归不在 Windows 上断言无效权限位。
- MBTiles 瓦片为含 NUL 的 TEXT 时，SQLite length 按字符计数，绕过读取前的大小预算。现对 BLOB 转换后的字节数检查；用 SQLite VIEW 复现，无需在 Go 生成或在磁盘写入超大瓦片。
- 本地目录/MBTiles 追加只更新平铺范围，内嵌完整 TileJSON 仍描述旧地区；下载合并还漏了 center。共用同步函数只更新已存在的标准范围字段，保留自定义字段。PMTiles 头仍为权威，不强制添加 JSON 可选字段。
- 交叉复核发现 JSON 重编码会舍入自定义大整数；同步及原有下载/PM 写出校验入口改为保留未知字段的原始 JSON，仅解码需要校验的 vector_layers。既有用例同时检查顶层与嵌套的 9007199254740993 不被舍入。此后又修复了 PMTiles 读取的扩展字段类型丢失，见下方往返审计。
- 覆盖投影把南世界边缘截到最后瓦片行的上边界，导致斜线漏瓦片。现先做 Mercator 投影，再裁剪到矩阵边缘。
- 线段穿越网格角点时，固定先走 Y 和累计 crossing time 都会使正反方向覆盖不一致。现固定比较端点顺序，用同一网格角点的叉积判断步进，保留半开网格的点归属，无需 epsilon 或额外数值阈值。

回归复用既有追加/CLI/边界测试，仅为缺失的实际入口和覆盖算法不变量补小用例；不增加新的测试框架或大规模随机压力任务。S3 条件读、分页、取消与分段清理再次核对后，未确认新的可复现问题。稳定源文件、单目标单写者及 Win7 尚未真机运行的边界仍适用。
