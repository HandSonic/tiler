## 明确边界

- Win7 使用固定 Go 1.20.14、MSVCRT、CGO SQLite，构建 amd64/386，并检查 PE 目标版本和导入。当前环境不能实际启动 Win7；交叉构建成功不等于真机运行验证。
- S3 协议回归使用本地 HTTP 模拟服务，覆盖签名请求、multipart、对象 metadata、条件读、错误和取消；未连接用户真实 AWS/MinIO 账户。
- PMTiles 支持 none/gzip，静态 WebP 可解码但不能编码成 WebP；动画 WebP、Brotli/Zstd/AVIF 明确不支持。
- PBF 不做完整 MVT 内容/schema 推断；拒绝明显的错误页面，非空有效内容及真实图层描述由数据源提供。空文件仍按失败处理。
- 每瓦片大小/像素及覆盖辅助索引分别有预算；worker 和保存队列按数量限制，并非全进程内存上限。Win7 32 位应保持默认低并发（3 fetchers、1 保存缓冲），不要对大瓦片提高到极端并发。
- 归档追加会先合并再重建；目录/S3 散瓦片逐个写入，取消时可能已有部分新瓦片完成。构建不保留跨进程转换断点，恢复能力见 [转换与补洞说明](archive-and-repair.md)。

本记录表示本轮已复现问题被修复，并给出可重复检查的范围；不能证明任何输入、服务和运行环境下都不存在未知问题。


## 后续精简复核

这次复核专门检查过度设计、测试成本和魔数，处理了以下问题：

- 删除未被实际入口调用的旧 cover 算法、数据库实验任务、地图列表/空桩函数及旧辅助方法；对应只有死 API 在使用的地图列表测试也移除。当前覆盖流程保留 Count/CountContext/Walk 一套实现。

- PMTiles 目录只解压一次；无压缩输入直接解析原始目录，不再先 gzip 后解 gzip。预算按输入、解压数据和条目分配计量，去掉不透明的倍数及 64KiB 预留。
- 元数据 16MiB 读写上限统一为 maxMetadataBytes；明确它是项目资源策略，不是格式规范。PM 根目录首 16KiB 与 512/4096 构建批量分别命名并标注性质；511 从最大根条目数派生。
- Windows 255 单段兼容上限与 32K UTF-16 模板解析预算分别命名。后者只限制解析工作量，不再声称保证加上输出根后的完整路径一定可写。GeoJSON 深度/累计解码预算、内存 geometry 深度、worker/队列防误配阈值均具名说明；不增加公开配置项或通用限制框架。
- 删除一条重复 S3 上限回归，保留会检查既有数据不变的较强用例；纯 SQL 大元数据测试改用内存数据库，仍验证真实 16MiB 边界；修正三项“任何错误都算通过”的宽松断言。
- CI 保留完整普通回归，再运行 short race 回归。唯一被 short 跳过的是 64MiB 随机数据压缩边界；它仍在完整普通测试中执行，无需让标准库压缩器在 race 下重复承担高成本。fuzz 常规只跑种子，未在每次 CI 重复三十万次随机执行。
