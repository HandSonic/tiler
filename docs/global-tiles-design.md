# 全球瓦片下载、分包与统一地图服务方案

状态：设计稿，尚未实现。基于 `256f1a5` 的现有代码核对；本文的 `block_tiles`、`serve`、`publish` 均为拟新增能力，不能在当前版本直接使用。

## 目标与默认部署

同一套 `tiler` 负责下载、续传、归档转换、发布和只读地图服务。Windows 提供现有 Win7 amd64/386 构建，优先使用 amd64 承载大数据集。用户启动服务后即可在浏览器预览，并通过一个 XYZ 地址使用全球地图。

默认工作流是本地分包 MBTiles 下载完成后直接提供服务；不要求另装数据库、Node、Redis、Docker 或 GeoServer。需要把数据放在 S3/MinIO 时，再将各包转换为 PMTiles，并由同一服务从对象存储按需读取。

默认沿用现有栅格下载能力；PNG/JPEG 可直接预览。PBF 可提供标准矢量瓦片接口，但完整底图的呈现还需要匹配的样式、字体和图标，不能自动从瓦片推导出这些资源。

## 分包规则：每个层级内的固定瓦片块

设 `N` 是每边瓦片数，一个数据集创建后固定。对全球 XYZ 坐标 `(z,x,y)`：

```text
bx = floor(x / N)
by = floor(y / N)
包路径 = z/bx/by.mbtiles
```

每个包只保存一个 zoom、最多 `N*N` 张瓦片，包内保留原始全球坐标。MBTiles 的 `tile_row` 仍按标准转换为 TMS 行号 `2^z-1-y`。不要改用包内局部坐标。

**不采用一个祖先区域包揽所有后续层级的规则。** 那种规则的单包数据仍会随最高层级增加约四倍；单层分块则是增加更高层级的包，不会令既有低层级包继续膨胀。

例如 `N=512` 时，请求 `z=14,x=13500,y=6200` 对应 `14/26/12.mbtiles`。该包中查的是原坐标 `z=14,x=13500`，内部 TMS 行号为 `10183`。

| 每边瓦片数 N | 每包最多瓦片 | 假设平均 20 KiB，满包瓦片数据 | 全球 z0–14 的包数 | 全球 z0–16 的包数 |
| --- | ---: | ---: | ---: | ---: |
| 256 | 65,536 | 约 1.34 GB | 5,469 | 87,389 |
| 512 | 262,144 | 约 5.37 GB | 1,374 | 21,854 |
| 1024 | 1,048,576 | 约 21.47 GB | 351 | 5,471 |

以上是选择参数的示例，不是硬容量上限，也不是当前性能测试结果。SQLite 页面、索引、日志和不同影像的压缩率另计。初始建议用代表性瓦片样本估算平均字节，再选择 N；没有样本时必须把容量标为假设值。

首版不实现“到指定 GB 自动换卷”，以免引入逐瓦片位置索引、重平衡和不稳定归属。若实际单包过大，需要用更小 N 转换到新数据集；不能在追加时悄悄改变 N。硬字节上限是独立需求，不能把 N 的数量上限宣传成硬字节上限。

## 数据集目录与兼容性

本地根目录包含 `dataset.json`、标准 MBTiles 包和已有失败记录。`dataset.json` 只描述布局版本、N、瓦片格式、网格、实际层级/范围、瓦片像素尺寸及来源标识；不保存密钥，也不建立逐瓦片索引。补洞记录仍使用已有失败清单语义。

每包都是可独立打开的标准 MBTiles，带本包范围和层级元数据。外部工具可以单独使用某个包；要把整套分包作为一个全球图层，则使用本文的统一服务。分包目录本身不是一种能被任意第三方软件自动识别的 MBTiles 标准扩展。

沿用当前格式边界：MBTiles 支持 z0–30，PMTiles 输出支持 z0–26；发布前检查实际层级，不能因分包而绕过格式/读取器兼容限制。

一个数据集保持相同地图图层、网格、格式、像素尺寸及矢量 schema。数据源鉴权参数更新沿用现有来源指纹规则，不能把原 URL 或 S3 密钥写入公开元数据。

所有分包路径均由校验过的数字坐标生成，限制在配置的数据集根目录内。已有本地/S3 散瓦片模板继续保留；分包内部使用确定布局，不把散瓦片路径模板硬套到数据库包名上。

## 下载、续传、追加和已有数据迁移

- 复用现有覆盖计算、下载重试、转码、MBTiles 写入和失败补洞；新增的是按坐标选择目标数据库。
- 瓦片从内存直接写入目标包，不先落单张图片，也不先生成一个全球巨型数据库再拆分。
- 分包调度和数据库连接数量均受限。优先按包组织覆盖范围、逐包或有限并行下载，避免按一条全球扫描线反复打开大量数据库；几万包不能对应几万打开句柄。
- 重启后按同一坐标规则定位包，检查实际已提交的非空瓦片。不能因为包文件存在就认为整个包完成。
- 追加 B 地区只修改 B 涉及的旧包或创建新包；重合坐标继续保留旧非空瓦片，A 地区不重建。提高最高层级时，创建对应新层级包。
- 中断或磁盘不足返回错误、保留已提交内容。重新运行完整原任务补齐未调度坐标；失败清单只负责已经记录的失败坐标。
- 整体范围与各包元数据遵循现有追加合并规则。元数据存在不代表全球已经下载完整；任务结果必须报告失败和取消。
- 现有本地/S3 散瓦片、单个 MBTiles/PMTiles 可通过扩展 `convert` 逐瓦片导入分包数据集；按目标包写入，不能将全部源数据先装进一个新数据库。
- 分包集导出单归档需显式选择；不会在发布或启动服务时自动合并为巨型文件。分包集转另一种分包格式逐包处理。

启动全球任务前，应报告瓦片数、包数、容量假设和可用磁盘。标准全球网格可用公式计数；复杂范围复用覆盖器计数，不创建全球坐标列表。所有累计计数使用 64 位整数。估计时间使用实际允许的下载速率，不把提高并发当成容量问题的解决办法。

全球 z0–14 共 357,913,941 张，若平均 20 KiB，纯瓦片约 7.33 TB；z0–16 则约 117 TB。分包改善搬运与访问，不降低这些数据的总量。尚无百 TB/PB 或任意复杂全球 GeoJSON 的性能验证，不能以现有小规模回归作为吞吐承诺。

## 内置地图服务

拟增加 `serve` 子命令，使用 Go 标准库 `net/http`、现有 SQLite 驱动和 PMTiles 解析能力。一个数据集对应一个稳定对外名称，例如 `world`。

| 地址 | 行为 |
| --- | --- |
| `/maps/world/{z}/{x}/{y}.jpg` | 默认 XYZ 栅格瓦片；扩展名匹配实际格式 |
| `/maps/world/{z}/{x}/{y}.pbf` | 矢量瓦片，正确提供内容类型及 gzip 响应 |
| `/maps/world/tilejson.json` | 统一范围、层级、像素尺寸和 URL 模板 |
| `/` | 内置地图预览，选择本服务已配置数据集 |
| `/healthz` | 进程就绪状态；不宣称所有全球瓦片齐全 |

HTTP URL 可配置为 z/x/y 或 z/y/x；TMS 行号反转单独明确。公开模板、请求解析和 TileJSON 必须一致，不能把交换目录顺序当作 TMS。

内置预览使用同源接口；接入其他网页时显式配置允许的 CORS 来源。HTTP 缓存校验值绑定返回字节或明确的包版本，更新数据后不能继续复用旧版本的长期缓存标识。

一次请求先验证坐标，再算出 `(z,bx,by)`，只查对应包。缺包或缺瓦片返回 404；非法参数返回 400；归档损坏返回 500；对象存储故障按上游异常/超时返回 502/504。鉴权失败、损坏或超时不能伪装成“没有瓦片”，也不默默用低层级图片替代缺失的高层级瓦片。

本地 MBTiles 用索引查询返回存储的原始瓦片，不在每个请求上重新解码转码图片。PBF 的 gzip 与 `Accept-Encoding` 正确协商，避免重复压缩。元数据发布统一图层描述。

归档按需打开，限制打开数量；限制并发读取和缓存总字节，缓存不按全球瓦片数增长。这些是可解释、可配置的运行资源预算，不是格式常量，也不承诺等于整个进程最大内存。首版本地读取优先利用 SQLite/系统页缓存，不另建全局图片缓存层。

栅格预览页面及依赖静态资源随程序提供，离线打开不访问 CDN。PBF 只有在提供匹配的样式和资源时才展示完整底图。服务器 Win7 兼容性与浏览器渲染兼容性分别验收，不承诺任意老浏览器都支持矢量 WebGL。

默认监听 `127.0.0.1`；局域网访问显式指定网卡或 `0.0.0.0`。服务只提供只读地图接口，不开放下载管理、任意磁盘路径或密钥信息。公网部署由受维护系统上的反向代理处理 HTTPS 和访问控制，Win7 核心使用要求不扩张为自建完整认证平台。

## 本地搬运与更新

第一阶段明确采用**停写后提供服务**：

1. 完成下载或补洞，提交事务并关闭数据库。
2. 复制整个数据集目录，或者直接在原机器启动服务。复制/发布前复用现有 WAL 与活动 journal 检查。
3. 在新机器以数据集根目录启动服务；前端始终使用统一 XYZ 地址。
4. 追加 B 时，停止该数据集服务并关闭归档句柄，再追加，完成后重启。只需搬运变化包并更新元数据；目标端亦停止该数据集服务后替换。

这一路径不要求为 MBTiles 再保存一份 PMTiles，也不需要复制一遍全部世界数据。第一阶段不支持同一数据集边下载边读取、跨进程同时写入或 Win7 上热替换已打开的归档；不能仅凭“服务只读”推断这些并发场景安全。

Windows 工作盘和搬运盘优先使用 NTFS。FAT32 的单文件上限约 4 GiB，不能因为已经分包就假定任意 U 盘都能保存；示例中的 5.37 GB 满包仍可能超过它。这里不自动格式化或改动用户的磁盘。

## S3 / MinIO 发布与在线读取

S3 在线发布采用 PMTiles 包；S3 上的 MBTiles 继续支持存档、下载和转换，不作为远程 SQLite 直接查询。

拟增加 `publish`：复用已有转换和上传，逐个将关闭的变化包转换为 PMTiles，上传后回收该包的临时文件。转换仍可能同时使用本包的临时 MBTiles、排序索引和结果包；需要按单包估算额外空间，不能承诺只占最后 PMTiles 的大小。

整个发布期间源数据集保持停止写入；同一目标前缀只允许一个发布进程。关闭后又被其他进程写入的源包不构成稳定快照，清单最后切换也不能替代并发发布控制；首版不支持这些并发操作。

发布采用不可变对象名及清单最后切换：

1. 为变化包生成新对象，未变化包继续引用旧对象；服务读取的对象不原位覆盖。
2. 记录包的稳定来源版本和生成结果校验值。版本由不复用的包身份与修订构成，或直接使用每次提交新生成的唯一标识；删除重建、外部导入或重新分包不能重用旧身份。瓦片及影响发布结果的元数据修改须在同一事务更新版本，避免崩溃后误判为未变化。外部修改无法验证版本时重新校验/生成，不能仅凭文件名或时间戳跳过。这一内部修订标记不覆盖用户填写的地图 `version` 元数据。
3. 上传并确认本轮全部对象成功，再生成完整新发布清单，最后更新活动清单引用。
4. 服务启动或显式重新加载时采用新清单，单次请求始终使用同一个清单快照。发布失败保持原活动清单。
5. 清单按包组织，不记录逐瓦片位置。若全球高层级包列表很大，按 z/bx 分片并按需载入，不能要求所有包都塞进一个无限增长的 JSON。
6. 不自动删除旧清单仍可能引用的对象；旧版本清理须在确认无引用后显式执行。

上传恢复区分两种能力：成功完成且校验一致的包可跳过；中途失败的那个包重新上传。现有 SDK 重试和 multipart 不是跨进程包内断点续传，首版不新增持久化 multipart 状态管理。

在线读取由服务根据同一分包规则找到 PMTiles 对象，再按 Range 读取头、相关目录和瓦片。浏览器仍访问服务的统一 XYZ 地址，不取得 S3 凭证，也无需配置成千上万个图层。服务沿用 `[output.s3]` 的明文凭证或 SDK 默认凭证链。

当前 `archiveWalkPM` 只适合遍历转换；新的服务读接口必须按 tile ID 查找目录并随机读取，不能在每次请求中扫描全部瓦片。底层使用本地 `ReadAt` 或 S3 Range，复用现有格式校验。Range 必须核对响应范围、长度及版本；头、目录、瓦片的缓存绑定对象版本，通过 VersionId 或 `If-Match` 防止混读。ETag 只作为不透明版本标识，不能当作内容 MD5。

PMTiles 对象本身不使用外层 `Content-Encoding: gzip`；其内部目录或瓦片 gzip 可以保留。上游忽略 Range、返回整包时应明确报错，不静默下载整个全球归档。

## 拟新增的使用入口

以下配置和命令仅用于说明设计，**当前版本尚不可执行**。

```toml
[output]
format = "mbtiles"
directory = "D:/maps"
name = "world"
append = true
block_tiles = 512 # 拟新增：每边瓦片数；未启用时保留现有单文件行为
```

```powershell
# 下载到分包工作目录；沿用原有 tm、lrs 与 task 配置
.\tiler.exe download -c world.toml

# 本地浏览与统一 XYZ 服务；缺省 listen 为 127.0.0.1:8080
.\tiler.exe serve -input D:/maps/world

# 局域网提供地图
.\tiler.exe serve -input D:/maps/world -listen 0.0.0.0:8080

# 可选：逐包发布到 S3 / MinIO，凭证留在服务端配置
.\tiler.exe publish -c world.toml -input D:/maps/world -output s3://maps/world/
.\tiler.exe serve -c world.toml -input s3://maps/world/
```

`serve` 的本地/S3 切换不改变前端瓦片地址。多数据集部署使用一个显式配置表映射名字到根目录或 S3 前缀，不开放从请求参数任意指定存储地址。

## 实施顺序与有限回归

**第一阶段交付完整本地闭环**：单层固定块路由、直接分包下载/续传/追加/补洞、已有数据导入、只读 MBTiles 服务、统一 TileJSON 和离线栅格预览。完成后用户已有可用地图系统，不必等云存储功能。

**第二阶段补齐 S3 闭环**：逐包 PMTiles 发布、发布清单、随机 Range 读取、成功包跳过、统一服务切换。复用现有转换和上传，不能把现有整包 GET 错当在线随机读取。

第一阶段不附加任务管理平台、分布式调度、自动负载均衡、逐瓦片全局索引或在线重分片；第二阶段的包版本清单只服务于多对象发布一致性。

回归围绕新行为的实际风险，复用已有格式和编码测试，不复制全格式×全布局×全存储矩阵：

- 分块边界、不同层级、XYZ/TMS/ZYX，通过同一服务请求得到原始瓦片。
- 中断后继续并追加 B，A 的非空重叠瓦片保持；改变 N 明确拒绝。
- 数据库关闭后搬到新路径仍可启动服务；活动 sidecar 明确拒绝。
- 缺瓦片、坏归档、S3 鉴权失败和超时得到正确区分，且资源限制生效。
- S3 Range、版本变更和发布中断不混读；失败发布不改变活动清单。

延续现有普通测试、必要的 race 检查和 Win7 amd64/386 构建。开发时先做一个跨包端到端用例，再用代表性实际数据测写入吞吐、冷/热读取及常驻内存。规模测试只在确有新瓶颈时扩大，不将全球 TB 数据下载放入常规 CI。

Go 1.20 是最后支持 Win7 的 Go 系列，继续沿用项目的 Go 1.20.14/MSVCRT 构建。交叉构建通过不等于 Win7 真机运行已验收；服务启动、复制后读包和实际 S3 HTTPS 都应在目标系统验收。

## 依据与现状核对

- 当前 `cli.go` 只有 `download`、`convert`、`upload`、`repair`，不存在 `serve`、`publish` 或自动分包。
- 当前 MBTiles 直接下载没有散图片中间产物，单归档转换和 S3 上传可复用。
- 当前 PMTiles reader 是遍历入口，S3 归档转换会整包下载；随机服务读属于新增能力。
