# 全球栅格瓦片分包与外部地图服务

当前方案采用标准 **Compact v2**：tiler 下载到本地 bundle，MapProxy 独立读取整套缓存并提供同一图层的 XYZ/WMTS 接口。此前讨论的自定义 MBTiles 分块布局未实现；不需要为它另写路由服务。具体配置、转换和使用边界见 [Compact v2 说明](compact-v2.md)。

| 部分 | 职责 |
| --- | --- |
| tiler | 下载、按瓦片续传、追加和补洞，生成 Compact v2，转换与上传 |
| Compact v2 目录 | 按层级和 128×128 网格存放 bundle，保存标准缓存元数据 |
| 独立 MapProxy | 按坐标读取对应 bundle，对外暴露一个图层 |
| 地图客户端 | 使用该图层的统一 XYZ 或 WMTS 地址 |

每包只保存同一级别最多 16,384 张瓦片。提高最高下载层级会增加 bundle 数量，不会把所有后代层级装进同一个区域包。包大小仍取决于图像压缩率：按每张 20 KiB 假设，满包瓦片数据约 320 MiB，另加索引和长度前缀；128 是格式标准规定的边长，不是可配置的容量阈值。

分包改善复制时的小文件数量，但不降低瓦片总量。全球 z0–14 共有 357,913,941 张瓦片，按每张 20 KiB 假设仍约 7.33 TB，约 21,852 个 bundle；不代表完成了全球下载或该规模的性能验收。实际容量应先从目标数据源采样估算。

下载直接写 bundle，不先生成一个全球 MBTiles 再拆分，也不落单张临时图片。追加下载只修改涉及的 bundle；向已有 Compact 缓存执行 `convert -append` 时，先验证新输入，再合并受影响的 bundle，不重建整个旧缓存。恢复或追加前会枚举旧缓存路径，拒绝可能造成重复坐标的非标准 bundle 命名；预检不读取包内容。正常取消后可以逐瓦片续传；不承诺突然断电时的跨文件事务原子性。

停止写入后，复制整个缓存根目录到地图服务机器，修改独立的 [MapProxy 配置](mapproxy-compactv2.yaml) 中的绝对路径、图像格式和瓦片尺寸。一个缓存对应一个图层，客户端不逐包配置。更新服务正在读取的数据前，先停止或切离该缓存，完成后重新加载；尤其不要假设 Windows 可以替换已被服务打开的文件。

S3/MinIO 用于整套 bundle 的存档和转换。MapProxy 示例读取本地路径；S3 存档需先同步到服务机器的本地磁盘或可靠挂载，不能把 `s3://...` 填进 `cache.directory` 就视为已经支持远程随机读取。

MapProxy 的部署、端口、鉴权及运行系统由外部服务负责。tiler 不内置 HTTP 服务或服务管理功能。下载器继续使用 Go 1.20.14/MSVCRT 构建 Win7 amd64/386 版本；构建检查不等于真实 Win7 运行验收。
