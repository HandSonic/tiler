# 全球瓦片下载分包与外部服务交付方案

状态：修订设计稿，自动分包尚未实现。`tiler` 保持下载工具定位，保留此前已要求的续传、补洞、格式转换和 S3 上传等输出处理能力。

本稿替代此前把地图服务装进 `tiler` 的方案。**不增加 `tiler serve`、`tiler publish`、HTTP 服务、预览页面、服务缓存、鉴权或发布版本管理。** 上一版只写了设计文档，没有实现这些程序功能。

## 职责边界

| 部分 | 职责 |
| --- | --- |
| tiler | 下载、续传、补洞，生成瓦片或标准归档，执行已有转换和上传 |
| 数据集 | 独立标准归档及必要的布局说明，方便搬运、导入 |
| 外部地图服务 | 读取归档、提供统一 XYZ 接口、处理访问与缓存 |
| 地图客户端 | 显示地图；矢量底图另需匹配的样式、字体和图标 |

地图服务独立部署、独立配置，优先评估已有工具；只有已选服务缺少分包路由时才考虑最小适配，不预先创建第二套服务框架。服务配置不塞进下载配置，服务代码和依赖不并入 `tiler`。

下载器的 Win7 要求继续保留。外部服务的运行环境与兼容性独立核实，不能因为某个服务不支持 Win7 就将它并入下载器。

## 下载分包的候选规则

设 `N` 是每边瓦片数，一个数据集创建后固定。对全球 XYZ 坐标 `(z,x,y)`：

```text
bx = floor(x / N)
by = floor(y / N)
包路径 = z/bx/by.mbtiles
```

每个包只保存一个 zoom、最多 `N*N` 张瓦片，包内保留原始全球坐标。MBTiles 的 `tile_row` 仍按标准转换为 TMS 行号 `2^z-1-y`。不要改用包内局部坐标。

**不采用一个祖先区域包揽所有后续层级的规则。** 那种规则的单包数据仍会随最高层级增加约四倍；单层分块则是增加更高层级的包，不会令既有低层级包继续膨胀。

例如 `N=512` 时，请求 `z=14,x=13500,y=6200` 对应 `14/26/12.mbtiles`。该包中查的是原坐标 `z=14,x=13500`，内部 TMS 行号为 `10183`。

| 每边瓦片数 N | 每包最多瓦片 | 假设平均 20 KiB，满包瓦片数据 | 全球 z0–14 的包数 | 全球 z0–16 的包数 |
| --- | ---: | ---: | ---: | ---: |
| 256 | 65,536 | 约 1.34 GB | 5,469 | 87,389 |
| 512 | 262,144 | 约 5.37 GB | 1,374 | 21,854 |
| 1024 | 1,048,576 | 约 21.47 GB | 351 | 5,471 |

以上是选择参数的示例，不是硬容量上限，也不是当前性能测试结果。SQLite 页面、索引、日志和不同影像的压缩率另计。初始建议用代表性瓦片样本估算平均字节，再选择 N；没有样本时必须把容量标为假设值。

首版不实现“到指定 GB 自动换卷”，以免引入逐瓦片位置索引、重平衡和不稳定归属。若实际单包过大，需要用更小 N 转换到新数据集；不能在追加时悄悄改变 N。硬字节上限是独立需求，不能把 N 的数量上限宣传成硬字节上限。

## 下载器中需要增加的最小能力

- 按坐标将下载数据从内存直接写入对应 MBTiles 包，不落散图片，也不先创建全球大库再拆分。
- 沿用现有续传和补洞语义，检查包内实际非空瓦片，不能把包文件存在视为整个包完成。
- 追加 B 只修改相关旧包或创建新包，保留 A 的已有非空重叠瓦片；增加层级时生成新层级包。
- 按包组织写入，限制数据库连接和队列数量，避免全球包数决定同时打开文件数。
- 记录必要的布局版本、N、格式、网格、实际层级/范围和来源标识；不写入密钥，不建立逐瓦片全局索引，不为服务发布引入包版本状态机。
- 复用已有失败清单。中断后完整重跑原任务可补齐尚未调度的坐标；清单或元数据存在不代表整个地区已下载完成。
- 扩展已有 `convert`，使散瓦片或归档可以导入分包目标，并逐包转换 MBTiles/PMTiles；继续复用 `upload`，不另设发布命令。

每包带本包元数据，是可独立使用的标准归档。整套目录的分包约定不等于任意第三方软件自动支持的标准，因此应先完成外部服务接入验证，再冻结布局和配置名称。沿用 MBTiles z0–30、PMTiles 输出 z0–26 的现有边界。

规划时同时报告瓦片数、包数和容量假设，不建立完整全球坐标列表。全球 z0–14 的 357,913,941 张瓦片按平均 20 KiB 估计仍约 7.33 TB；分包不降低数据总量，也不意味着已经完成百 TB/PB 性能验证。

## 搬运、追加与 S3

本地使用 MBTiles 时，不默认再保存一套 PMTiles。下载完成、事务提交且数据库关闭后复制数据集及必要布局说明。复用现有非空 WAL/活动 journal 检查，不能将仍在写入的数据库当作完整快照搬运。

追加或替换外部服务正在使用的包前，先让该服务释放相关文件，再修改或复制，完成后重新加载。尤其不能假定 Win7 可以替换已打开的文件；下载器不负责启停外部服务。Windows 工作盘与搬运盘优先使用 NTFS，FAT32 的单文件上限约 4 GiB，示例满包可能超过它。

S3/MinIO 存档沿用现有上传能力。外部服务需要远程读取时，可以逐包转为 PMTiles；Range 在线读取由该服务承担。S3 中的 MBTiles 仍可存档、下载和转换，但不能假定服务可直接远程查询 SQLite。

逐包转换仍需本包的临时数据库、排序索引及新归档空间，不同时转换全球所有包。SDK 重试不是跨进程包内续传，现有上传失败后仍需重传该归档。多对象上线顺序、活动清单及旧版本清理由外部部署流程负责，不扩张为下载器的发布平台。

## 外部服务的接入约定

统一地图访问仍属于整套方案的目标，由外部服务对客户端提供例如 `/maps/world/{z}/{x}/{y}.jpg` 的单一图层地址，并按分包规则选择归档。客户端不逐个配置所有包。

服务选型至少验证：

- 支持实际使用的栅格/矢量格式，以及本地 MBTiles 或 S3 PMTiles。
- 能按坐标将多个包作为同一图层访问，或通过小范围路由适配实现；支持多个归档不等于自动合成全球图层。
- 只查询相关包，限制打开文件数量，不为每次请求扫描全部归档。
- 正确处理 XYZ/TMS 行号、瓦片编码和缺失响应，满足实际部署系统要求。

例如官方 `pmtiles serve` 按 `TILESET` 暴露归档接口，不等于已经实现本稿的分包统一路由。这仅是选型依据，不是已经确定或部署的服务方案。

先用相邻块两侧的几张真实瓦片跑通独立服务的统一地址，再确定下载分包输出。服务适配的代码、依赖和验收在独立项目维护，不并入下载器；不因本稿而新建自研服务框架。

## 实施与验证范围

先验证外部服务接入，再实现下载分包、续传追加及已有转换/上传衔接。保持现有单文件和散瓦片输出，不删除此前已要求的能力。

下载器回归只覆盖新增行为的关键风险：块边界与层级归属、TMS 行号、中断后续传和追加保留旧瓦片、布局参数不一致拒绝、关闭后复制及活动 sidecar 检查。复用已有格式、压缩和 S3 测试，不复制全格式与全存储矩阵，也不增加 HTTP 服务测试。

保留 Go 1.20.14/MSVCRT 的 Win7 amd64/386 构建。实际下载、复制和 S3 HTTPS 仍需目标系统验收。本轮只修订文档，没有添加或删除现有程序功能。
